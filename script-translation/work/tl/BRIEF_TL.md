# 번역투 고치기 지침 (기신비상 아르곤 교정본, 2026-11-01)

機神飛翔デモンベイン(기신비상 데몬베인)의 한국어 번역을 다듬는다. 번역은 이미 원문과 대조해 검수를 마쳤다. 남은 일은 일본어를 그대로 옮겨 생긴 **번역투**를 자연스러운 한국어로 바꾸는 것이다. 사용자 지시는 「번역투를 다 고쳐」다. 단, **진짜 번역투만** 고친다. 애매하면 그대로 둔다.

## 입력

`P:\AI\khd-argon-review\work\tl\partN.json`(맡은 파일 하나)은 칸 목록이다. 칸마다 다음 필드가 있다.

- `sid`: 칸 ID
- `speaker`: 화자. 지문이면 `(지문)`
- `hits`: 걸린 패턴 이름
- `cell_jp`, `cell_ko`: 이 칸의 원문과 현재 한국어
- `unit_jp`, `unit_ko`: 같은 문맥 전체. `unit_ko`의 `[T00012]`는 칸 경계, `[R…]`는 루비 읽기 칸이다.
- `prev_unit_ko`: 바로 앞 문맥의 끝부분. 「그것」이 무엇을 가리키는지 볼 때 쓴다.
- `ruby_neighbor`: 이 칸 바로 앞이나 뒤에 루비 읽기 칸이 붙어 있으면 true

## 출력

`P:\AI\khd-argon-review\work\tl\outN.json`(N은 맡은 번호):

```json
{"agent": "tN", "edits": [{"sid": "da0101:T00032", "old": "…", "new": "…", "cat": "번역투", "reason": "原文「…」 패턴 설명"}], "kept": 37, "notes": "패턴별 고침/둠 수, 질문"}
```

- `old`는 그 칸의 현재 한국어에 **정확히 한 번** 나오는 가장 짧은 부분 문자열이다. 고칠 곳만 감싼다.
- `new`는 그 자리에 들어갈 글이다.
- 한 칸을 여러 번 고치면 편집을 여러 개 쓴다. 앞 편집의 결과에 이어서 적용된다.
- 다 쓰면 반드시 검사기를 돌리고 오류가 0이 될 때까지 고친다.
  `python -I -X utf8 P:\AI\khd-argon-review\tools\check_proposals.py P:\AI\khd-argon-review\work\tl\outN.json`
- 다른 파일(`out/responses` 등)은 절대 고치지 않는다. 제안 파일만 쓴다.

## 꼭 지킬 것

1. **최소 고침.** 번역투인 구절만 바꾸고 나머지 문장은 글자 그대로 둔다. 문장을 새로 쓰지 않는다.
2. **칸 구조.**
   - 칸 사이로 글을 옮기지 않는다.
   - `ruby_neighbor`가 true이면 칸의 첫 낱말과 끝 낱말은 건드리지 않는다. 그 낱말의 조사는 루비 읽기와 짝을 이룬다.
   - 칸 안의 `\n`, 줄 앞 전각 공백 `　`, 문장부호(「」『』……――!?)를 그대로 둔다. 문장을 합치거나 나누지 않는다.
3. **뜻·말높이·말투.**
   - 뜻을 바꾸지 않는다. 반말·존대·하게체를 바꾸지 않는다.
   - 인물의 말버릇은 번역투처럼 보여도 그대로 둔다.
     - 닥터 웨스트의 「~なのであーる」를 옮긴 「~인 것이다아」
     - 알의 예스러운 말투(「~하노라」, 「~이니라」, 1인칭 「이 몸」)
     - 윈필드의 격식체
     - 치아키의 경상도 사투리
     - 베스파시아누스의 예스러운 존대
4. **낱말.**
   - 고유명사·용어·루비 관련 낱말은 바꾸지 않는다. 外道=외도, 蠱毒=고독은 작품 용어다.
   - 한자 괄호를 쓰지 않는다. 대사에 「그/그녀」를 새로 넣지 않는다.
   - 흔한 한자어(전신·최후·장소·격렬)는 취향으로 고유어로 바꾸지 않는다.
5. **다른 번역을 보지 않는다.** 예전 빌드, 남의 패치 등은 쓰지 않는다. 원문과 현재 한국어만 본다.
6. 애매하면 고치지 않는다. 고친 수보다 정확도가 중요하다.

## 패턴별 요령

| 패턴 | 고치는 경우와 방법 | 그대로 두는 경우 |
|---|---|---|
| 「~에 의해/의한」 | 원인은 「때문에·으로」, 수단·재료는 「~로」. 행위자가 있는 피동은 행위자를 주어로 세운 능동으로 바꾼다(「크투가에 의해 뚫렸다」→「크투가가 뚫었다」). | 그 표현이 가장 자연스러울 때 |
| 「~와 동시에」, 「~함과 동시에」 | 「~자마자」, 「~자」, 「~면서」로 바꾼다. | 실제로 두 일이 같은 때임을 강조할 때 |
| 「~한/인/는 것이다」, 「~것이었다」 (のだ) | **기본은 평서형으로**(「존재하지 않는 것이다」→「존재하지 않는다」). | 말버릇, 절정의 결론처럼 빼면 강조가 사라질 때, 인용·제목 |
| 「가득 차 있다」 | 「가득하다」, 「넘친다」로 바꾼다. | 공간이 물리적으로 꽉 찬 모습을 그릴 때 |
| 「~정도의」, 「~정도로」 | ほど를 뻣뻣하게 옮긴 경우에만 「만큼」으로. 「느끼게 하지 않을 정도의」는 「느낄 수 없을 만큼」. | 「어느 정도」, 「그 정도」, 숫자+정도, 이미 자연스러운 「~할 정도로」 |
| 「~에 대해(서)」 | ～のこと·について의 기계적 직역이면 목적어로 바로 받거나 「~에 관해」, 「~ 이야기」로. | 자연스러운 경우 |
| 「~로부터」 | 「~에서」, 「~에게서」, 「~께」로 바꾼다. | 문어체로 꼭 필요할 때 |
| 「그것은/을/이」 | それ를 기계적으로 옮겨 어색할 때만. 가리키는 것을 밝히거나(「그 사실」, 「그 모습」, 「그 일」) 뺀다. **보수적으로.** | 대부분. 그것은 평범한 한국어다. |
| 「~적인/적으로」 | 「대규모적인」, 「통상적인」, 「기형적인」 같은 어색한 직역만 「대규모의」, 「평소」, 「일그러진」 식으로. | 자연스러운 「~적」 |
| 「~하지 않으면 안 된다」 | 「~해야 한다」로 바꾼다. | – |
| 이중 피동(「되어지다」 등), 「~에 있어서」, 「~할 터인」 | 단순 피동, 「~에서/에게」, 「~할」로 바꾼다. | – |

## 끝나면

`notes`에 패턴별로 고친 수와 둔 수를 적는다. 판단이 갈리는 칸은 고치지 말고 `notes`에 sid와 이유를 적는다. 마지막 답에는 출력 파일 경로, 편집 수, 검사기 결과만 짧게 쓴다.
